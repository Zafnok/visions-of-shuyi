# 0180 — A command writes shuyi.ron's disclosure lists from the files they allow

## Context

`shuyi.ron`'s `disclosure` parts (ticket 1208, ADR-0120) say what a
release package may hold. There are four: the full game's (line 169)
and the `demo`, `story-preview` and `story-trial` editions' (lines 741,
1111, 1366). Each has `allowed_files` and `allowed_pack_entries`, and
every line is a copy of something the tests can already compute. So
the lists work as a lockfile, not a review: a new music track is 5 hand
edits, a voice clip 3 (`vix_ccefa1ae` is at lines 400, 527 and 920), and
a new content file is a public `shuyi.ron` edit. `shuyi.ron` grew from
553 to 1,624 lines over PRs #616–#735, and `music/` now appears 241
times for 48 tracks. #664 and #728 added lines by hand in several places,
and #699 failed on a list mismatch. See retro T17 in
[the retrospective](../../docs/research/retro-2026-11-17-prs-616-735.md).

The tests that keep the lists equal to the computed sets are in
`crates/xtask/src/game_tools/tests.rs`:
`the_disclosure_list_names_the_music_voices_and_licenses_a_package_ships`
(line 712), `the_demo_edition_holds_the_full_games_files_and_its_canaries_only_the_later_chapters`
(740), `the_trial_edition_is_the_demo_less_the_scripts_with_no_later_name`
(789) and `the_disclosure_lists_name_every_file_of_the_pack` (1514).
Nothing checks `story-preview`'s `allowed_pack_entries`.

The engine (`shuyi-cli`'s `project::Disclosure`) reads plain lists only:
no include, glob or `extends`. So this ticket generates the lists inside
`shuyi.ron`; it does not shrink the file. This is the third copy of the
same list, so the `engine-friction` skill is run too (ADR-0092).

## Scope

**In:**
- `cargo xtask disclosure` (writes) and `--check` (fails on a stale list).
- Generated `allowed_files` and `allowed_pack_entries` in all four parts.
- One test that runs the check, in place of the list-equality asserts.
- An `engine-friction` review and its row in `docs/engine/friction.md`.

**Out (do not do):**
- `canaries` and `forbidden_paths`: they stay written by hand, with the
  tests that check them (they are a judgment, not a copy).
- Any change to the engine's disclosure format, or to what a package may
  hold. If the friction review says "engine feature" (for example
  `extends` with dropped prefixes, or a folder rule like `music/*.ogg`),
  the `engine-change` skill files it, with Nick's OK first; this ticket
  does not wait on it, and shrinking `shuyi.ron` is that ticket's job.
- `crates/content/build.rs` and `demo_bundle.rs` (how editions are cut;
  1288 changes their parsers, not `Plan`'s API). Either order with 1288.
- The Playdate's lists. Either order with 1170: if 1170 is done, its
  pack entries and baked `.pda` files become sources of steps 2–3 here;
  if not, 1170 writes its lines by hand and adds them to this module's
  sources later (1170's disclosure bullet says so).
- The voice test's skip without `voice/` (0177). Either order: if 0177 is
  done, keep its `voice_or_skip` call in the test that replaces it.

## Implementation steps

1. New module `crates/xtask/src/disclosure.rs`, registered in
   `crates/xtask/src/main.rs` beside `Some("check-leaks")` (line 105).
   It loads `shuyi_cli::project::Project::load(&repo_root())`.
2. **`allowed_files`, per part:** walk the part's `beside` list (the
   `export` part's for the full game, each edition's own). A file is its
   `name` or file name; a folder (`music`, `assets/audio/licenses` as
   `audio-licenses`, `voice` when it is there) is every file under it,
   as `files_under` in `tests.rs` line 851 does (move it into the
   module). Add the pack (`<package>.pack`). For the full game only, add
   the `visions-of-shuyi.app/Contents/Resources/` copy of each folder
   file and of the pack, as today. The demo's has no `.app` lines.
3. **`allowed_pack_entries`, per part:** full is
   `Bundle::new(trpg_content::bundle::pack_layers()).files_under("")`;
   demo is `demo_layers()` less `bundle::is_private` paths (as the test
   at line 1514 does); `story-preview` is the full set less the rules in
   `crates/content/story-preview/bundle.txt`; `story-trial` is the demo's
   less `crates/content/story-trial/bundle.txt`. Read both lists with
   `trpg_content::demo_bundle::Plan::parse` and `Plan::left_out`, the
   parser the build uses; write no parser of their rules here. Sort each
   list.
4. **Write by markers.** Put a comment line before and after each
   generated list in `shuyi.ron`
   (`// generated by cargo xtask disclosure: demo.allowed_files` and
   `// end generated`). The command replaces only the lines between,
   at the list's indentation, and keeps every other comment.
5. **Without the private checkout** (`bundle::skip_without_the_game()`,
   or no `voice/`): writing refuses and says to run
   `cargo shuyi private-assets`. The check compares only what it can:
   every computed line is listed, as the tests do today.
6. Replace the list-equality asserts in the four tests above with one
   test, `the_disclosure_lists_are_what_xtask_disclosure_writes`, whose
   message names the command. Keep their canary and forbidden-path asserts.
7. Rewrite the comments that say "a new track or voice clip needs its two
   lines" (`shuyi.ron` lines 159–168 and 534–538, `docs/releasing.md`
   lines 64–67 and 70–72) to "run `cargo xtask disclosure`".
8. Run the `engine-friction` skill on this copy and add its row.

Expected size: about 250 production lines and 100 of tests, less the
asserts removed; `shuyi.ron` changes only by the marker comments.

## Acceptance criteria

- [ ] The first `cargo xtask disclosure` run leaves every list in
      `shuyi.ron` byte for byte as it was: only marker comments change.
- [ ] Adding a file to `music/` or a test clip to `voice/` and running
      the command adds every line it needs, with no hand edit;
      `the_disclosure_lists_are_what_xtask_disclosure_writes` fails until
      then.
- [ ] `story-preview`'s `allowed_pack_entries` is checked.
- [ ] `docs/engine/friction.md` has this review's row.
- [ ] All gates in the `run-gates` skill pass.

## Tests required

- Unit: the marker splice keeps other lines and comments; a folder
  `beside` gives its files under its name; the `.app` copies.
- Integration: the check test above, on the real `shuyi.ron`.
